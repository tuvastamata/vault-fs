# HZ-FS-0001: Reference notes written on the Linux developer machine reach the operator only by hand; captures and push-backs can be lost between the two copies

**Hazard:** The operator works from a stale process flow or checklist while the master has moved on, or a capture pulled into the snapshot is curated while a newer one sits on Drive; a push-back written locally never reaches the machines.

**Cause:** The hub-and-spoke flow assumes Google Drive for desktop on every machine (`SETUP.md`, Part C), but it has no Linux client. On the developer's machine `~/factory.sale/fs-vault-sync` is an rclone snapshot pulled by hand; push-backs are copies into that snapshot and must be uploaded separately. The vault-curation skill reads the snapshot and writes push-backs into it as if it were a live mirror.

**Details:**
- `fs:HANDOFF.md@89d77d2` + the uncommitted edit of 2026-08-27 ("Sync caveat"): the snapshot is "a manual snapshot (zip export), not a live mirror — push-backs written there must be uploaded to the shared Drive folder by hand".
- Last pull: 2026-08-27 13:37 (backup `~/factory.sale/.rclone-backups/fs-vault-sync-before-andrei-pull-20260827T133716`); the first copy of 2026-08-18 came as a zip export.
- One push-back pending since 2026-08-27 ([[DC-FS-0002]]); the shared folder's newest changes are vault-sh 2026-08-27 13:45 and vault-ops 2026-08-18 12:07 ([[FACT-FS-0001]]).

**Consequences:**
- The operator's reference notes drift from the master; the single-inbox rules (labels, send-as) may be followed from an older note.
- Captures can be curated twice or missed if the snapshot date is not recorded per run.

**Check:**
- `rclone lsl andrei:vault-ops/reference` against `ls -l ~/factory.sale/fs-vault-sync/vault-ops/reference`.
- `rclone check andrei: ~/factory.sale/fs-vault-sync --one-way` — what Drive has that the snapshot lacks.
- The curation log `fs:skills/vault-curation/.curation-log.md`: every PUSH-BACK row names the upload or says it is pending.

**Mitigation:**
- End every curation run with `rclone copy` (push-back) or `rclone bisync` (both ways) and write the command and time into the curation log; the federation runs `rclone bisync` for the colleagues' vault already.
- Record the snapshot's pull time at the top of each PULL run.
- Longer term: a Drive client on the developer machine or the Drive connector for push-backs.
